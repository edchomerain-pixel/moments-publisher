## 已整合的行为

- Telegram可信会话及发送者白名单、标准入站路径限制、最多20张manifest、摘要绑定、串行处理锁、逐图失败隔离、重复跳过和续跑保留。
- 新增本机Vision OCR筛查，裁剪后无识别文字的图片走上传；有文字的图片进入repair_pending；来源标记进入rights_review。这是保守文字筛查，不是可靠水印鉴定；商品文字可能误报，图形/淡色/斜排水印可能漏检。
- 检测器缺失或报错停止该张上传。原图和候选图在本机私有目录留存；不输出识别文字。不处理用户消息正文中的命令。来源确认要求跨重试保留，不能因下次OCR未识别而绕过。
- 本机人工验收修复结果的回传入口已测：须确认已审核；来源标记另须确认使用权；再经文字筛查和上传摘要回执。该入口不是ChatGPT自动修复，也未向非技术用户宣称可全自动。
- 正式相册候选记住成功验证的HTTPS只读连接，打开/前台/联网后扫描所有云端分页，前台每分钟复查；失败退避重试。每张校验大小、类型、SHA256与解码再独立存入原相册；旧照片、文案与编辑不覆盖。
- 新记录按云端上传时间参与原最近更新排序；不重新编号或重写旧记录。v1→v2仅新增dismissed墓碑表，用户删除云图记录后不自动重现；不删除云端对象。
- 当前设备网站存储保存读取凭据，不是系统钥匙串；网站数据清理可能丢失连接与本机数据，Safari与主屏PWA存储上下文需分别确认。iOS页面关闭时不承诺后台同步。

## 最终用户流程核对

手机Telegram发送一批约20张截图 → OpenClaw接收 → CleanPic裁剪、检测分流 → 普通图自动上传；疑似残留文字/水印留队，后续可靠AI修复并验证后才回传 → 打开原巴商相册自动同步显示。

常规使用不要求浏览收件箱、勾选或手动保存。首次连接/读取凭据轮换后在iPhone主屏相册里更新一次连接属于必要设置；后续重开自动恢复。当前普通链路本地候选已验证，正式发布与真机批量仍待执行；AI全自动修复未实现。
